# M3-001 — واجهة الأخبار

## الهدف

تتحول مساحة الأخبار في الصفحة الرئيسية إلى واجهة قابلة لعرض أخبار العمارة عند
توفر مصدر بيانات لاحقًا. إلى ذلك الوقت تعرض حالة فارغة صادقة بدل الإعلان
المثبت الوهمي الحالي.

## الحالة والاعتماديات

`READY`. المهمة مستقلة عن M1/M2 لأنها واجهة عرض تستقبل بياناتها عبر مدخلات
صريحة، بلا قراءة أو كتابة خادمية. لا تبدأ ربط Supabase في هذا الفرع.

## النطاق

- نموذج عرض بسيط للخبر: معرف ثابت، عنوان، نص، وقت النشر، `isPinned` و`isImportant`.
- مكوّن الصفحة الرئيسية يعرض أحدث خبر متاح، أو العبارة
  «لا توجد أخبار منشورة بعد» إذا كانت القائمة فارغة.
- شاشة «أخبار العمارة» تقبل قائمة أخبار من المستدعي، وتعرض كل عنصر بعنوانه
  ونصه ووقت نشره وشارة مثبت/مهم عند الحاجة، مع رجوع واضح للصفحة الرئيسية.
- ترتيب حتمي: المثبت أولًا، ثم الأحدث حسب `publishedAt`، ثم `id` تصاعديًا
  عند تساوي الوقت. لا تؤثر شارة «مهم» وحدها في الترتيب.
- دعم العربية RTL وتباين الثيمات وتسميات دلالية لقارئ الشاشة للعناوين والشارات.

## حدود التنفيذ

- لا أخبار وهمية داخل مسار التطبيق الفعلي؛ يمكن للاختبارات حقن عينات صناعية.
- لا Supabase أو API أو إشعارات أو تحرير/نشر أخبار أو صلاحيات جديدة.
- لا تلمس بطاقات المستحقات أو الدفع أو المصروفات في هذه المهمة.
- لا بيانات سكان حقيقية ولا أسرار.

## القبول والتحقق

- اختبار Widget يثبت الحالة الفارغة بالنص المحدد وعدم عرض خبر وهمي.
- اختبار Widget يثبت ترتيب المثبت ثم الوقت ثم المعرف، مع شارات «مهم» و«مثبت».
- اختبار Widget يثبت فتح قائمة الأخبار والعودة، ووجود تسميات قارئ الشاشة.
- `dart format --output=none --set-exit-if-changed .` و`flutter analyze`
  و`flutter test` و`flutter build apk --debug` تمر في CI مع Secret scan.
- PR مستقل على فرع `codex/`، ويُحدّث `Skills used` والأدلة بعد التنفيذ.
