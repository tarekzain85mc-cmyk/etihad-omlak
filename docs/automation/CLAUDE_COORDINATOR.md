# Claude coordinator automation

## التشغيل الأول

من PowerShell داخل المستودع شغّل:

```powershell
.\scripts\start-claude-coordinator.ps1
```

وافق بنفسك فقط إذا كنت تثق في مجلد المشروع، ثم راجع طلب تفعيل Context7.
السكريبت لا يتجاوز Workspace Trust ولا يوافق على MCP تلقائيًا.

## المهمة المستمرة

اقرأ `CLAUDE.md` و`docs/plan/UNIFIED_PLAN.md` وافحص الـPRs المفتوحة وتعيين
المهام. اختر أصغر مهمة `READY` أو `PLANNED` غير مسندة إلى منفذ آخر ولا تعتمد
على قرار منتج مفتوح. أنشئ brief وفرعًا أو worktree منفصلًا، نفّذ الاختبارات
المناسبة، وافتح PR بدل الكتابة المباشرة على `main`.

## حدود الأتمتة

- لا auto-merge لتغييرات auth أو RBAC/RLS أو المالية أو الدفع أو migrations أو الأسرار أو الإصدار.
- لا Production ولا بيانات سكان حقيقية ولا endpoints حية.
- Strix ساكن فقط؛ أي اختبار نشط أو managed upload يحتاج موافقة جديدة منفصلة.
- 21st يبقى معطلًا حتى يتوفر مفتاح خارج Git.
- أبلغ فقط عند نجاح مرحلة، فشل CI، blocker متكرر، أو قرار مطلوب.
- لا تعتبر GitHub Actions ناجحًا قبل مرور Secret scan وFlutter checks فعلًا؛
  مشكلة الدفع أو حد الإنفاق عائق حساب خارجي وليست نتيجة اختبار.

## أدلة كل تشغيل

- الفرع والـcommit والـPR.
- الملفات والمهارات المستخدمة.
- أوامر الاختبار ونتائجها.
- أثر الخصوصية وRBAC/RLS والمالية وخطة الرجوع.
